# Team Rules

Reglas de trabajo colaborativo para el desarrollo del proyecto StudentHub.

## Uso de Ramas

- La rama main es estable y no se modificará directamente.
- Todo desarrollo nuevo debe hacerse en una rama de trabajo (ejemplo: feature/nombre-funcionalidad).

## Mensajes de Commit

Los mensajes de commit deben ser claros y utilizar los siguientes prefijos:

- feat: para agregados o nuevas funcionalidades.
- docs: para cambios en archivos de documentación.
- fix: para correcciones de errores o errores tipográficos.

## Pull Requests y Revisión

- Todo cambio hacia la rama main debe integrarse mediante un Pull Request.
- Se requiere la revisión y aprobación de al menos un compañero antes de realizar el merge.

## Resolución de Conflictos

- En caso de conflicto de fusión, el equipo debe acordar la versión final antes de subir los cambios.
